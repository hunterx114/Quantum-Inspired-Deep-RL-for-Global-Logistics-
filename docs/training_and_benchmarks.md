# Training and evaluation

## Training

`src.training.train` loads environment, reward, learner, curriculum, and run
settings from YAML. It logs episode rewards, reward components, stage, steps,
and losses to TensorBoard. Model and optimizer state dictionaries are saved
periodically and at the end of a run.

```powershell
python -m src.training.train --learner maddpg
python -m src.training.train --learner tn_maddpg
tensorboard --logdir outputs/tensorboard
```

The curriculum changes fleet and port sizes, so a promotion constructs a
correctly sized learner. Compatible per-ship actor layers and existing port
logits are transferred, with the speed output moved to the new final action
slot. Newly added actors/port logits are initialized for the new stage; the
central critic and replay buffer are rebuilt because their joint dimensions
changed.

The sweep command performs real independent training runs over bond dimension,
learning rate, noise type, and batch size. It writes one CSV row per completed
run; each run's TensorBoard logs and checkpoint are kept in its output folder.

```powershell
python -m src.training.sweep --bond-dims 4 8 --learning-rates 0.001 --noise-types ou gaussian --batch-sizes 32
```

## MADDPG comparison

The comparison benchmark records p50/p95 inference latency, online-plus-target
parameter count, additional process CPU RSS, GPU peak allocation when CUDA is
selected, decisions per second, and measured environment reward. Inference
timings include five warm-up calls by default. Pass matching trained
checkpoints to compare trained policies:

```powershell
python -m benchmarks.compare_agents --maddpg-checkpoint outputs/checkpoints/maddpg/maddpg_final.pt --tn-checkpoint outputs/checkpoints/tn_maddpg/tn_maddpg_final.pt
```

Without checkpoints, the script measures fresh initializations; their rollout
rewards are not evidence of trained-policy quality. Results are saved as
`tn_vs_maddpg.csv` and `tn_vs_maddpg.png` under `outputs/benchmarks`.

## Disruption evaluation

`benchmarks.stress_eval` runs a matched no-disruption baseline and four
deterministic interventions: port closure, fuel-price spike, a hub/neighbor
closure cascade with a fuel spike, and a storm front across selected routes.
It reports event-window reward drop, SLA percentage-point drop, and recovery
time under a configurable reward-recovery tolerance. By default it uses a
seeded random policy; use `--policy maddpg` or `--policy tn_maddpg` with a
matching checkpoint to evaluate a saved policy.

```powershell
python -m benchmarks.stress_eval --policy tn_maddpg --checkpoint outputs/checkpoints/tn_maddpg/tn_maddpg_final.pt
```

All benchmark values are generated by the selected run and hardware. Short
smoke runs verify the pipeline but should not be treated as statistically
meaningful model comparisons.
